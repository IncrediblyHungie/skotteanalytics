Open · Case Study

LLM-as-Judge Orchestration Pipeline

A personal-infrastructure project: a multi-source data pipeline that scrapes 30 heterogeneous sources (Workday, Phenom, Oracle Cloud, Greenhouse, custom APIs), then uses an LLM as a structured judge — every record scored against a versioned rubric with a validated, typed verdict contract — and routes qualified results to alerts.

  • Parallel orchestration: 24 independent lanes on a thread pool, rate-limit-aware per host — benchmarked 6.3× faster than sequential (270s → 43s, identical coverage, same-day A/B on live sources)
  • Reliability engineering: idempotent state, atomic writes, per-record retry caps with loud give-ups, lockfile with heartbeat, crash-safe resume — a record can be delayed, never silently lost
  • LLM rigor: fenced untrusted input (prompt-injection tested), envelope validation, verdict normalization, double-sampling on positive verdicts, every judgment logged to an append-only ledger with the rubric version that produced it
  • Airflow-ready: the same topology expressed as an Airflow DAG with dynamic task mapping and pooled concurrency
